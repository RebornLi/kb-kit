## 二、四项交付

### 1. 复合置信分 ✅ 并已接进排序

四因子（照搬 Engram 的可审计配方，权重可查）：

```
confidence = 抽取方式×0.50 + 佐证数×0.25 + 新近×0.15 + 校验通过×0.10
```

`kb confidence show --rel <笔记>` 能回答**为什么是 0.787**：

```
extraction 0.9×0.5=0.45 + corroboration 0.35×0.25=0.087
  + recency 1.0×0.15=0.15 + verification 0.6×0.1=0.06
```

**踩到的坑（值得记）**：第一版四因子用**粗档位**（1 条=0.4、2 条=0.6…），结果
668 篇正典的置信分**只有 7 个不同取值、全挤在 0.748–0.843**——档位把分辨率吃光了。
改成连续量纲（佐证用 `log2` 平滑、抽取按推断占比线性、新近线性衰减）后才有区分度。

**第二个坑**：绝对阈值没用。正典**全都过了三关**，绝对分天然集中，按 0.55 卡会把
668 篇全判成 publish（等于没分档）。改为**相对分位**（canon 群体内 p10 / p3）
+ 绝对地板：

```
publish 627 · review 35 · evidence-only 6
```

排序乘数 `×{1 ± 0.2·(conf-0.5)·2}`（即 0.5→×0.9，1.0→×1.1），并入了原有分层降级里。

### 3. 矛盾在环 ✅（本轮最有价值的发现）

确定性检测：**主题重合（结论区 Jaccard） + 变更信号（改为/不再/废弃/取代/纠正…）**。

调参过程（每步都有数字）：

| 版本 | 候选对数 | 问题 |
|---|---|---|
| 初版（Jaccard ≥0.25） | **195** | 太吵 |
| + 排除同族碎片 | 37 | 仍有"自己跟自己" |
| + 用 `root_of` 排除同根族 | 22 | 仍偏高 |
| **+ 区分「近似重复」与「真冲突」** | **真冲突 12 · 近似重复 10** | ✅ 可行动 |

**关键发现**：那 22 对 99–100% 重叠的"冲突"，其实是**同一份内容被结晶了两遍**——
同源碎片各自结晶，产出两个文件名不同、内容几乎相同的正典（只是空格/措辞微差）。
这是**重复**不是矛盾。于是：

- 冲突检测器把它们分出来 → 进 `.kb/duplicate_canon_queue.jsonl`（走去重/合并）
- **根治**：`curate` 写回前新增 **dup 闸门** `find_dup_canon()`（结论区相似度 ≥0.90 即判重复），
  命中就标 `skip:duplicate-of(...)` 而不新建。实测能正确识别那对真实的"正典双胞胎"。

标注动作（`kb contradict apply`，默认 dry-run）：写 `conflicts_with` frontmatter +
正文 `> ⚠️ 与 [[X]] 存在冲突` callout + 入人工队列。**绝不自动删改**。

### 4. 原则性遗忘 ✅ 审计先行，**什么都没删也没降**

`kb decay`：零命中 + 陈旧（>120 天）+ 低重要度（<0.4）+ 低置信，四项中命中 ≥3 才建议降层。

当前结果：**668 篇 → 建议降层 0 篇**（正典都很新且很少低重要度）。
纪律写进输出：**降层 = 退出主检索，文件与原文始终保留，`kb raw` 随时调回**。

## 三、又抓到两个真 bug

1. **`CONF_WEIGHT` 未定义** —— 我把常量插到函数 docstring 里，实际没定义。
   查询直接 `NameError` 崩掉。
   **更值得记的是它怎么被发现的**：评测脚本把子进程崩溃当成"0 命中"，
   于是指标显示 `canon@K 0.0%` —— 数字荒谬到反而暴露了问题。
   已修：评测脚本对子进程非零退出**大声报错**，不再把崩溃当空结果。
2. **顺序依赖**：Jaccard 在中文 unigram 下天然偏高（同主题就 0.9+），
   单靠阈值调不出好结果；必须叠加"同族排除"这个**结构性**约束才可用。

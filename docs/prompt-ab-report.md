# 提示词 A/B 报告（P1）

> 目的：判断「四层契约化提示词」是否真的优于生产中的紧凑提示词（baseline）。
> 方法：**同一批笔记、同一模型（ornith1.5-35b）、同一校验规则**，只换提示词，比较
> JSON 合法率 / 三关通过率 / 耗时。三轮迭代，每轮 3–6 篇。

## 结论（先说）

**四层结构没有赢。** 三轮里 baseline 在通过率上均不劣于 layered，且更快。
因此：

- **默认走 `baseline`**（`kb curate run`，与 P0 前生产环境一致）
- 四层结构保留为可选：`kb curate run --prompt layered`，待更大样本证明后再切默认
- 但 P1 的**校验侧升级全部保留**（它们抓到了真问题，见下）

## 三轮实测

| 轮次 | 样本 | baseline 通过 | layered 通过 | layered 主要失败原因 |
|---|---|---|---|---|
| 第 1 轮 | 6 篇 | **3** | 2 | 压缩偏轻（ratio 0.67–0.89）被旧 `MAX_RATIO=0.65` 判死 |
| 第 2 轮 | 3 篇 | 2 | 0–1 | JSON 截断；facts 未接地 |
| 第 3 轮 | 4 篇 | **3** | 2 | facts 未接地 1 条 / 未给 sources / 标识符覆盖偏低 |
| 第 4 轮（最终档位对齐） | 4 篇 | **3** | 2 | 同上 |

耗时：layered 平均 **62.6s/篇** vs baseline **43.9s/篇**（提示词更长、模型思考更久）。

## 过程中发现的两个真问题（比 A/B 结果更重要）

### 1. `MAX_RATIO` 与接地关互相打架

第一轮 layered 的失败清一色是「几乎没压缩：67%–89% > 65%」。但看事实：
**layered 保留得更多、压得更少**，而接地关（facts 必须回原文逐字找到）本身就在奖励"忠实保留原文措辞"。
两个判据方向相反 → 忠实提案被误杀。

**处置**：`MAX_RATIO` 从硬失败降为 ⚠️ 警告。内容是否靠谱交给接地关与覆盖关判定。

### 2. 真正该测的是两件事，不是字符比

用户的验收标准是「**没有无用字符、没有废话、逻辑清晰**」。据此把判据换量纲：

| 旧判据 | 新判据 | 为什么 |
|---|---|---|
| 字符压缩比（min/max） | **标识符覆盖**：原文里的命令/路径/端口/版本/时长/服务名，正典覆盖了多少 | 字符守恒 ≠ 信息守恒；标识符才是"不能丢"的东西 |
| — | **蒸馏度**：原文里寒暄行 / 指令性开头 / 高频重复行的占比 | 直接对应"没有废话"这一目标 |

实测这两条判据都能抓住真问题：

```
标识符抽取（去噪后）：['/home/mushan/models/Qwen', '0.0.0.0', '0.26.0',
                      '0.0.0.0:8000', '121.69GiB', 'vllm-chat.service']
寒暄识别：'好的，收到'/'嗯嗯，继续'/'好的好的' → True
         '操作步骤：先跑基线'/'这条结论很重要'/'继续深入排查根因' → False
```

抽取器踩过的坑（都修了）：
- 把表格分隔当标识符（`| 默认 dry-run |`）→ 现在拒绝含 2 个以上 `|` 的串
- 从长路径里切出碎片（`/嵌入模型`）→ 路径必须 ≥2 段
- 裸大写词（`TODO`/`LTS`）噪声太大 → 删除该模式
- 覆盖关样本 <8 时统计噪声大 → 现在 ≥8 才判定，且从硬失败降为警告

## P1 的净交付

| 交付 | 状态 |
|---|---|
| `reference/kb-schema.json` 作为单一契约 | ✅ 页面类型 / 必填节 / 字段 / 置信分档 / 陈旧策略 |
| `pipeline/curate_prompt.py` 提示词层 | ✅ 四层组装 + 范文库（从已通过校验的正典自动挑选）+ 两种档位 |
| 契约驱动的**页型校验** | ✅ `kb curate` 现在会检查「必填节是否齐全」「节名是否在契约内」 |
| **facts 分型** | ✅ verbatim / extracted / inferred；inferred 不计入接地分母，且正文须带 `^[推断]` |
| **覆盖关 + 蒸馏关** | ✅ 取代字符压缩比（压缩比降为参考指标） |
| 默认档位 | ✅ `baseline`；`--prompt layered` 可选 |

## 下一步（P2 更有价值）

A/B 的教训是：**在提示词上抠半天，收益不如改检索与分块**。
Anthropic 的实测是「上下文检索 + 上下文 BM25」把 top-20 失败率降 **49%**，加 reranker 降 **67%**——
比任何提示词微调的收益都大。所以按原方案推进 **P2：父子分块 + 上下文串 + RRF + 嵌入 rerank**。

# 概念索引（本库自有术语的集中定义）

> 用途：回答「正典是什么」「契约检查什么」「置信分怎么算」这类**问本库自身**的问题。
> 为什么单独建一篇：这些概念散落在各份 P0–P4 报告里，单篇关键词密度低，
> 检索时会被大量"讲 kb-kit 但不讲该概念"的长文挤下去。集中定义 = 提高可检索性。

## 正典（canon）
- **定义**：由本地模型结晶产出、经三关校验后写回的知识条目；frontmatter 标 `kb_layer: canon`。
- **特征**：结论优先（结论/依据/操作/坑与边界）、带 `source_ref` 可回溯原文、有 `confidence` 置信分。
- **检索地位**：排序 ×1.25 提升，是检索优先命中的**唯一目标层**。
- **与原文的关系**：原文保号在 `raw/_curated/<原路径>`，`kb raw show "<source_ref>"` 一键取回。

## 结晶（curate）
- **定义**：把原始记录（会话日志/操作流水/碎片）炼成可调用正典的过程，命令 `kb curate`。
- **三关校验**：接地关（facts 逐条回原文核对）· 信息守恒关（尺寸感知长度比）· 引用关（sources 可达）。
- **两关质量闸**：标识符覆盖（命令/路径/端口/版本是否保住）· 蒸馏度（寒暄与重复是否删掉）。
- **子命令**：`plan` 选批 · `run` 结晶（默认只出提案，`--apply` 写回）· `verify` 离线重校验 · `report` 指标 · `review` 待裁决。
- **置信闸门**：模型自评 <0.6 不自动写回，进人工队列。

## 知识契约（schema）
- **定义**：`reference/kb-schema.json`，声明页型、字段、枚举、置信分档、陈旧策略的**单一事实源**。
- **检查什么**：`kb schema check` 查 —— 必填字段缺失 / 枚举越界 / 类型与范围错误 /
  canon 缺溯源 / `archived_original` 指向不存在的文件 / noise 未退出检索 / 证据层越界 / summary 超长。
- **分级**：`enforced`（越界即报）vs `aspirational`（自由标签，仅建议归一）。
- **用途**：提示词按契约注入页型与必填节；校验按契约判合规。

## 复合置信分（confidence）
- **公式**：`抽取方式×0.50 + 佐证数×0.25 + 新近×0.15 + 校验通过×0.10`（四因子可审计）。
- **可解释**：`kb confidence show --rel <笔记>` 能回答"为什么是 0.787"。
- **分档**：相对分位（正典群体内 p10/p3）→ `publish` / `review` / `evidence-only`。
- **排序作用**：`×{1 ± 0.2·(conf-0.5)·2}`，即 0.5→×0.9、1.0→×1.1。

## 双时态（bitemporal）
- **event_at**：该事实**何时为真**（取原记忆时间）。
- **derived_at**：该条**何时被学到**（结晶时间）。
- 分开存才能回答"当时知道什么"。

## 矛盾在环（contradiction）
- **检测**：结论区主题重合 + 变更信号（改为/不再/废弃/取代/纠正…）。
- **区分**：真冲突 vs **近似重复**（同一内容被结晶两遍 → 去重，不是冲突）。
- **处置**：写 `conflicts_with` + 正文 `> ⚠️ 与 [[X]] 存在冲突` callout + 入人工队列；**绝不自动删改**。
- **根治**：`curate` 写回前有 dup 闸门（结论区相似度 ≥0.90 即判重复，跳过不新建）。

## 原则性遗忘（decay）
- **判据**：零命中 + 陈旧（>120 天）+ 低重要度（<0.4）+ 低置信，四项中 ≥3 → 建议降层。
- **纪律**：降层 = 退出主检索，**文件与原文始终保留**，`kb raw` 随时调回。

## 证据层（raw / evidence）
- **内容**：`raw/` 网页抓取物（`is_source: true`）+ `memory/` Agent 日报 + `raw/_curated/` 结晶前的原文保号副本。
- **纪律**：**原文保真，永不改写**；默认不参与主检索（排序 ×0.72），但 `kb raw show/find` 始终可调用。

## 分层与降级（kb_layer）
- 五层：`canon`（×1.25）· `page`（×1.0）· `raw`（×0.72）· `index`（不入索引）· `noise`（不入索引）。
- 同一根文档的碎片按 `chunk_of`/文件名链归并，每个根家族最多出 2 条命中（防"碎片墙"）。

## 上下文强化（CCH / Contextual Retrieval）
- **做法**：把标题/路径/域/标签/首句拼成一行上下文，**只写进索引文本，不改 .md 正文**。
- **为什么**：分块后每块脱离原文会失去意义（"它涨到 200"不知道"它"是谁）。

## 父子块（parent-child）
- 索引子块（便于匹配），命中后回填**父块正文窗口**（便于推理）。
- 父页若只是目录页，则改用"同父下得分最高的兄弟碎片"。

## 混合检索（hybrid / RRF）
- 两路：TF-IDF 余弦 + BM25；用 **RRF**（`Σ 1/(60+rank)`）融合，对分数量纲免疫。
- 加成：标题/路径匹配 · 倒排命中 · 同义词双向扩展（`reference/synonyms.json`）。

## 黄金集评测（gold / RAGAS 四指标）
- **四指标**：faithfulness（是否都在上下文里）· answer_relevancy（是否答在点上）·
  context_precision（召回是否噪声）· context_recall（该召回的是否都召回了，**需 ground truth**）。
- **命令**：`kb eval run` · `kb eval gold --generate/--review` · `kb eval compare`。
- **裁判**：本地模型（零成本、不出机器）；结果只用于**同一套题目内部**比较。

## 重排与开关（KB_RERANK / KB_TITLE_BOOST / KB_SYNONYM_EXPAND）
- **默认全关**，依据是 30 题黄金集的受控实测（禁查询缓存）：
  不重排 **canon@K 88.7% · top1 90% · top3 70%**；
  开 cross-encoder 重排 → top1 63%；开标题加权 → top3 60%；开同义词扩展 → canon@K 88.3%。
- **为什么重排有害（非参数问题）**：重排器优化"语义相似度"，而本库要的是"能否回答问题"。
  首段已用元数据强信号（分层/置信分/同族去重/标题），cross-encoder 看不到这些，
  会把"读起来像在讲这话题"的领域笔记顶上来，挤掉"真正回答了问题"的工程报告。
- 机制全部保留（环境变量可开），默认值按数据走；换库/换题后应复测。
- cross-encoder `bge-reranker-v2-m3` 在 :8082，50 条仅 45ms（快且便宜，但方向不对）。

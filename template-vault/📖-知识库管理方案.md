# 📖-知识库管理方案

> 本一键套件把"方案 v4.0"落地成了可移植的工程。正文要点如下；完整方案可另存。

## 一、理念
知识库像**有机体**：有新陈代谢（清洗/归档）、有免疫系统（巡检）、会自我连接（补链）、会按间隔回忆（recurrence）。

## 二、目录与命名
- 一级分区见 `🏠-知识库首页`。
- 文件名：主题清晰，分块用 `-p1`/`-p2`；示例页统一 `.md`。

## 三、元数据（frontmatter 规范）

| 字段 | 必填 | 取值 |
|------|------|------|
| `tags` | ✅ | `[daily]/[moc]/[template]/[decision]/[领域]` |
| `status` | ✅ | `draft→active→stable→legacy→archived` |
| `domain` | ✅ | 运维/开发/安全/产品/数据/管理/综合（跨领域元认知/模板/决策归 `综合`）|
| `category` | ✅ | `project`/`experience`/`reference`/`sop`/`meta`（英文 token，见下方双轴说明）|
| `created` / `updated` | ✅ | `YYYY-MM-DD` |
| `importance` | ✅ | `0.0–1.0`（T2 外部接地加权 + 人工复核，重要标 1.0）|
| `kb_target` | 路由必填 | 目标路径 |
| `kb_action` | 路由必填 | `append/update/new/retire` |
| `kb_summary` | 路由必填 | 一句话摘要 |

> **双轴分类（`domain` × `category`）**：每篇笔记用两个正交维度定位——
> - **`domain`（领域，中文）——"这是哪一行"**：运维/开发/安全/产品/数据/管理/综合。跨领域的元认知、模板页、决策页归 `综合`，不在 `domain` 单列。
> - **`category`（笔记类型，英文 token）——"这是什么类型的笔记"**：`project`（有起止的项目）/`experience`（已沉淀经验/复盘）/`reference`（查用不更新）/`sop`（标准流程）/`meta`（关于知识库本身）。模板/决策/纯元认知页靠 `category` 区分。
> - 旧笔记由分类迁移脚本 `pipeline/kb_schema_migrate.py` 统一补全 `category`；新增笔记请显式写好两轴。RSI 引擎 T1 据此做同域去重、同域补链；收件箱按 `category` 只给归类**建议**（自动归类风险高，仅提议、人工确认），符合防塌质量门。

## 四、成长引擎（pipeline/）
- `intake_triage.py` ① 摄入 triage
- `feedback_loop.py` ② 命中信号
- `link_engine.py` ③ 孤岛补链
- `recall_schedule.py` ④ 间隔回忆（按 importance 分档：L4 180d / L3 30d / L2 14d / <0.3 7d，urgency=importance×(1+逾期/稳定性)）
- `kb_health.py` / `dashboard.py` ⑤ 健康与治理面
- `clean.py` 清洗/分块 · `validate.py` 校验 · `rag.py` 本地检索

## 五、运维
- 备份/演练：`scripts/` 里 `backup_now.sh`、`drill_now.sh`
- 定时节拍：`scripts/growth_cron.sh`（可选 cron）
- 巡检：`scripts/healthcheck_cron.sh`

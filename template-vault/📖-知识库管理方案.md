# 📖-知识库管理方案

> 本套件把「一套会自成长的知识库」落成可移植的工程。本文是本库的结构、约定与维护说明。

## 一、理念
知识库像**有机体**：有新陈代谢（清洗/归档）、有免疫系统（巡检）、会自我连接（补链）、
会按间隔回忆。日常你只负责输入，维护交给引擎。

## 二、目录
见 `🏠-知识库首页`：`00-收件箱` / `10-项目` / `20-技术` / `30-决策日志` / `40-资源库` /
`50-模板` / `60-运营` / `70-知识治理` / `90-归档`。

> `domain`（领域，中文）与 `category`（笔记类型，英文 token）是正交两轴；收件箱归类只给
> **建议**，人工确认。`retire` 的笔记会被增量索引移除、不参与检索；仅 `status∈{active,stable}`
> 入检索（**来源权威**）。

校验与清洗：`kb validate [--strict]` / `kb clean dry-run|apply|chunk|refine|taxonomy`。

## 四、成长引擎（已接入 CLI）
- 检索：`kb query [--exclude-stale]` · `kb rag index`（`rag.py`，TF-IDF+BM25 混合）
- 摄入：`kb ingest` / `kb ingest move|trash`（`intake_triage.py`；合并写墓碑/别名/lineage）
- 清洗：`kb clean refine`（结构化+去重→分块→重建索引→校验）· `kb clean taxonomy`（标签归一）
- 反馈：`kb feedback [ingest|apply|hit]`（`feedback_loop.py`）
- 补链：`kb link [suggestions|apply|moc]`（`link_engine.py`；`moc` 生成知识地图）
- 回忆：`kb recall [deck|mark --grade …|status]`（`recall_schedule.py`，SM-2 间隔重复）
- 巡检：`kb healthcheck [all|deadlinks|…|freshness]`（`kb-healthcheck.py`）
- 度量：`kb health-metrics` · `kb dashboard`（`kb_health.py` / `dashboard.py`）
- 同步：`kb sync […]` · `kb memory-sync [review|promote]`
- 其它：`kb classify` · `kb graph` · `kb validate` · `kb user`

## 五、运维
- 备份：`kb backup [daily|weekly]`（`backups/<kind>/<date>-vault.zip` + `.sha256`）
- 恢复演练：`scripts/drill_now.sh`；定时节拍：`scripts/growth_cron.sh`；巡检：`scripts/healthcheck_cron.sh`

## 六、扩展
功能与 Agent 适配器都是插件：放入 `pipeline/plugins/`、定义 `PluginBase` 子类即被发现；
`reference/plugin-config.json` 启停；旧命令名由 `kb_launcher.COMPAT_MAP` 兼容。

> 研究层（RSI/反馈阶梯）为内部模块，仅 `kb rsi` / `kb compile` 暴露 CLI；由
> `tests/test_reachability.py` 显式登记。

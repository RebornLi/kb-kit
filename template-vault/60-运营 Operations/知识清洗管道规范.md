# 🧹 知识清洗管道规范

> 规则来源：[[📖-知识库管理方案.md|📖-知识库管理方案]]。成长引擎按此节拍自动维护知识库。

## 每日节拍（可选 cron，见 `scripts/growth_cron.sh`）

1. **建索引** → `kb rag index`（供后续检索）。
2. **收件箱 triage** → `kb ingest`（只读，写 `intake_triage.md`，四维打分）。
3. **命中信号** → `kb feedback ingest`（写 `feedback_hits.md` 与状态）。
4. **回忆 deck** → `kb recall deck`（写 `recall_deck.md`）。
5. **补链建议** → `kb link suggestions`（只读，写 `link_suggestions.md`）；采纳由人工 `kb link apply`。
6. **治理面** → `kb dashboard`（刷新 `70-知识治理 Governance/_INDEX.md`）。
6b. **知识地图** → `kb link moc`（刷新 `70-知识治理 Governance/_MOC.md`）。
7. **记忆侧** → `kb memory-sync promote` + `kb ingest agent`（Agent 记忆落 KB）。

> 可选每周：`kb clean refine`（结构化+去重→分块→重建索引→校验）、`kb clean taxonomy --apply`（标签归一）。

## 人工动作（审后再跑）

- 收件箱路由：`kb ingest move`（先 `kb ingest` 看清单再动；合并会写墓碑/别名/lineage）
- 命中提升：`kb feedback apply`（提升 importance，只升不降）
- 补链写入：`kb link apply`
- 回忆标记：`kb recall mark --grade again|hard|good|easy`
- 记忆晋升：`kb memory-sync promote`

## 铁律

- 任何 `apply` / `move` 写前**先 `dry-run` / `review` 看清单**。
- `importance` **只升不降**，防刷票。
- 脚本只 `git add` 自己改的文件，绝不 sweep Obsidian 运行时态。
